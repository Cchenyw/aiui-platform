# Windows 远程执行节点接入预研设计

日期：2026-11-15。目标：为 11 月 16 日接入 2–3 台独立 Windows 执行服务器准备可运行、可本地验证的首版。

## 已确认的方向

父平台承担统筹和结果汇总；各服务器运行执行节点、MCP 和浏览器。用户已确认 Windows 为主、执行节点主动连接父平台领取任务、执行后回传；单任务预算保留，共享预算后续实现。本机没有公司环境访问能力，交付必须区分本地验证与现场待验证事项。

## 方案与选择

- 继续由父平台推送任务：代码改动少，但需要服务器向外提供执行端口，跨机进程启停和网络可达性耦合，暂不作为远程首选。
- **主动领取任务（已选择）**：执行节点只需主动访问父平台；注册、心跳、领取、日志及结果均走同一远程接口。保留原有本地 push 节点。
- 仅外部结果上报：适合接已有外部测试系统；本期先完成平台创建任务的闭环，外部自主运行导入后续单独定义。

## 首版范围

1. 独立工作分支 `codex/research-remote-executors`，保持本地启动、用例、Profile、截图、AI 预算兼容。
2. 执行机标识 `machine_id` 对应服务器；`node_id` 对应执行进程。一台机器可以运行多个不同 ID 的节点，首版每节点默认并发 1。
3. 平台新增可选执行端网关监听；管理 HTTP 服务默认仍是 127.0.0.1。远程网关仅提供执行协议，不开放管理页面、用例编辑、LLM 配置或本地进程启动接口。
4. 每节点独立凭证，服务端配置保存 SHA-256 摘要，客户端从环境变量或本机凭证文件读取原文；凭证与 runtime 不进入 Git。节点身份、允许使用的 MCP ID、并发上限由服务端策略确定，不能由注册请求提权。
5. Windows 远程执行入口使用现有 `Agent._execute`；MCP 命令和路径在执行机解析。执行机使用自身的 LLM 配置，平台不自动复制个人电脑上的密钥或绝对路径。
6. SQLite 本地待上传队列保存未确认日志与结果；网络恢复后自动补传。服务端对事件去重，防止重复结果计费和日志重复。
7. 已领取任务的身份和执行批次持久化；父平台重启后仍能接受该批次的补传结果。尚未领取的任务及原有本地任务暂沿用当前重启中断语义，不宣称具备完整持久化调度队列。
8. 提供 Windows 部署配置、凭证生成/接入检查工具、PowerShell 启动示例和本机三节点验收脚本。

## 网络与凭证

- 默认网关关闭；启用时提供节点策略文件。管理端与执行端使用不同端口。
- 非回环地址部署使用 HTTPS：提供证书/私钥和执行端 CA 路径配置，保持证书校验。仅本地或显式允许的实验环境使用 HTTP，文档不建议关闭证书校验。
- 协议版本固定 `1`，POST JSON；节点 ID 与凭证绑定。校验节点策略、请求体类型、Content-Length 和 64 MiB 请求上限。错误不回显 token、Profile 原文或 LLM 密钥。
- 每节点策略必须包含来源 IP/CIDR 白名单，按实际 socket 对端地址校验，不信任 X-Forwarded-For；缺省仅允许回环来源。部署时填写服务器的实际出站地址。
- 随机 `instance_id` 持久化在节点状态目录，同目录使用进程锁保证单进程运行；重启复用该 ID，新状态目录产生新 ID。同一 node_id 的第二个在线实例被拒绝。
- 未完成分配绑定 node_id + instance_id + dispatch_id；未确认领取只能重发给原 instance_id，绝不因新实例注册把旧任务转交。新实例不能恢复另一个状态目录的任务，旧分配继续占用容量并显示待确认；旧实例仅可补传自己已分配批次的日志和结果，不能覆盖新实例的心跳或领取新任务。
- 网关停用/删除凭证后的节点不能继续领取或上报；首版修改策略后重启网关生效。

## 执行协议

网关提供 `/v1/register`、`/v1/heartbeat`、`/v1/claim`、`/v1/events`；具体错误结构及类/函数命名由实现者确定。凭证通过 Authorization Bearer 发送，不放 URL。

- 注册：机器/节点/实例 ID、显示名、OS、版本、能力、MCP ID、请求 slots；服务端取策略允许值与节点声明的交集。
- 心跳：报告活动 dispatch ID，确认已经收到的任务。父平台容量以持久化的未完成分配为准，不直接相信客户端 running 计数。
- 领取：按既有优先级选择匹配任务，匹配 MCP、所需能力、可选目标节点及空闲容量。不能让不兼容的队首任务阻塞整个远程队列。
- 普通任务保持现有自动调度；运行表单/API 新增可选 target_node_id，指定时仅该节点可以领取/接收。已有本地节点不会抢走指定远程节点的任务，验收脚本使用显式目标验证三节点。
- 任务先持久化分配，再返回；网络丢失领取响应时，未确认分配可重发同一个 dispatch_id，不能新建一次执行。
- 日志/结果事件包含 event_id、task_id、dispatch_id。服务端检查归属后才写入；旧批次不能覆盖新批次。重复确认是成功，不反复增加成本/统计。
- 接收确认必须区分 received/duplicate/rejected；客户端只删除确认接收或重复确认的事件。认证失败、未知任务或过期批次显示明确诊断，不把 HTTP 200 一律当成功。
- 结果继续使用现有 trace、截图、Profile 采集、usage、budget 数据结构；截图随结果发送并按既有安全方式落盘。大结果超限必须明确告警并保留本地未确认数据；截图分片与对象存储后续实现。

## 失联、重启与执行语义

- 远程节点失联后停止分配新任务，已领取的任务进入“待回传/状态待确认”，不直接分配给其他机器；避免旧机器仍在执行导致重复业务操作。恢复后允许同一批次补传结果。
- 父平台重启：从持久化的远程分配与已有 run 快照恢复待回传任务；保留 dispatch_id 和预算快照，不能只依赖内存 self.tasks。
- 分配与 run 状态更新在同一 SQLite 事务提交后才返回领取；重发 Profile 任务时按分配时的 profile_hash 加载不可变版本，不能读当前最新版本。完成记录与事件去重需要保证崩溃后重传仍不重复计费；日志插入和日志事件去重在同一事务提交。
- 执行节点领取后先写本地记录，再执行；相同 dispatch_id 重复到达不会重复执行。执行前持久化 running 标记。
- 执行节点进程重启：原 running 任务上报“执行节点重启，执行状态未知”，不自动重新执行；已生成但未确认结果继续补传。尚未开始的已领取任务可继续执行。
- 这是保守的至少一次消息投递 + 执行去重方案，不承诺对外部网站业务操作的 exactly-once。人工重新运行需要新 dispatch_id。

## 调度与 MCP 边界

远程节点声明所支持的 MCP ID，父平台只分配双方允许的配置。平台本机探测结果不能视为远程机器的环境证明，提供执行端自检并保留实际 list_tools 校验。

MCP stdio 在每个执行任务内启动；共享 HTTP MCP 的容量和状态隔离仍由 MCP 服务及后续资源配额解决。本期默认 slots=1；推荐官方浏览器 MCP 使用 `--isolated`，持久目录配置不自动改写。Profile 复用仍要求相同 MCP，快照在执行端独立加载。

保留单任务 token/步数预算快照。不同机器调用同一 LLM API key 的总限额、RPM/TPM、共享费用预算、账号互斥以及 MCP 资源池均不在本期实现。

## 管理界面

在执行节点页单独展示远程节点的机器、节点 ID、连接方式、状态、MCP 能力、占用/容量和最近心跳；不能将其标为需要添加本地配置的“未纳管”进程，也不提供误导的本地启动/停止按钮。允许查看断线节点及待回传任务，运行详情保留来源节点和批次信息。

## 验证与交付

- 单元测试：鉴权/越权、请求限制、能力和容量匹配、三节点领取、重复领取、事件去重、旧批次、父平台恢复、节点重启、断线补传。
- 本地集成：独立临时数据库/端口，模拟三台 Windows 机器（不同 machine_id/进程/状态目录）；运行本地测试页，汇总结果和截图；测试一次丢 ACK、一次节点离线以及父平台重启。
- 保留现有测试全绿；可用 mock LLM 验证 AI 协议和预算，避免调用真实付费模型。浏览器集成使用当前机器可用浏览器。
- 部署说明列出 Python/Node/浏览器安装、节点策略、LLM 配置位置、内网地址、HTTPS/防火墙、服务账号目录权限、工作目录与 UTF-8 要求、启动/停止及故障定位。
- 公司网络、实际 Windows Server 版本、服务账号权限、代理、证书信任、目标网站、LLM 出口均为现场验收项；本地进程模拟不等于公司三台服务器已经接通。

## 预研参考与环境基线

建议现场先采用 Python 3.12；代码最低保持 Python 3.10 语法兼容，具体依赖以现场安装验证为准。本机已安装 Python 3.15.2、mcp 2.3.0、Playwright 1.65.0、Node 26.13.0，本机测试不代表已覆盖 Python 3.12 和所有 Windows Server 版本。

- [Playwright Python 官方安装说明](https://playwright.dev/python/docs/intro)：当前官方系统要求包括 Windows Server 2019+；旧版服务器需要现场另行确认兼容版本。
- [Playwright 浏览器安装说明](https://playwright.dev/python/docs/browsers)：浏览器安装目录与运行账号相关，现场需要用实际服务账号确认安装路径及权限。
- [Python 3.12 ssl 文档](https://docs.python.org/3.12/library/ssl.html)：客户端使用默认校验上下文或显式 CA 文件，服务端使用证书链与私钥，不实现跳过证书校验选项。

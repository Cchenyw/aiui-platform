# 每步执行截图

用户希望在运行详情中看到每一步的页面场景，尤其是点击失败、遮挡和弹窗。

## 行为

- scripted 和 ai 模式每个实际工具步骤结束后，自动截取当前视口；失败步骤也尝试截图。
- 每步增加截图缩略图，点击打开原图；历史运行显示“未采集”，不支持截图的 MCP 或采集失败显示原因。
- 图片用于人工查看，不作为模型输入，不改变原步骤的通过/失败判定。
- 截图沿用任务 MCP 会话，限时 5 秒，并受任务剩余时间约束；不增加模型规划轮次。
- 截图字节随结果回传，由平台保存到 runtime/screenshots/，数据库只保存文件引用、采集时间和格式。
- 只接受 PNG/JPEG，单张最多 8 MiB；平台图片接口只提供该运行记录引用的图片。
- 旧任务不补拍，AI 的 __finish__ 不是浏览器步骤，不单独截图。

## 方案比较

1. 每步结束后截图（采用）：能看到执行后的状态；失败时能查看错误后的遮挡/弹窗，开销较小。
2. 每步执行前后各截图：对比更充分，但图片数量、传输与存储开销翻倍；本次不采用。
3. 仅失败截图：开销最小，但缺少用户要求的完整过程；本次不采用。

## 技术选择

沿用 Python 标准库、现有 MCP 和服务端渲染，不增加依赖。内置 MCP 新增 screenshot；官方 MCP 使用 browser_take_screenshot；EA MCP 使用 playwright_screenshot。读取 MCP 图片内容，不依赖外部 MCP 的本地文件路径。使用随机文件名及 task_id 哈希目录隔离重试和不同运行；文件路由校验引用和目录范围。

## 验收

单元测试覆盖三种 MCP 截图、失败/不支持/超时、文件持久化与非法文件访问；真实 scripted 和 Mock AI 演示覆盖浏览器采集、结果落库及失败截图；浏览器检查缩略图、原图和历史记录显示。
